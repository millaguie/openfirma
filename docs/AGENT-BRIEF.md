# Brief for agents working on this repository

Read this first, then README.md, docs/architecture.md, docs/validation.md and
the ADRs in docs/adr/. Everything below is a rule, not a suggestion. A change
that violates any of it fails review no matter how good the feature is.

## What this project is

openfirma is a from-scratch, pure Rust reimplementation of AutoFirma, the
electronic signature client published by the Spanish government (CTT). No code
is copied from AutoFirma. Output must be structurally identical to AutoFirma's
and must validate in VALIDe and in ETSI validators. Licence:
GPL-2.0-or-later OR EUPL-1.1, same as the original.

Reference material on this machine (not in the repo, may be absent elsewhere):

- official AutoFirma 1.9 jar: `/tmp/opencode/autofirma-bin/extracted/data/usr/lib/Autofirma/autofirma.jar`
- AutoFirma 1.9.1 source clone: `/tmp/opencode/autofirma-src` (module per format;
  `afirma-core-keystores` is the map of system keystore access)

## The method: golden first, implementation last

For any format or behaviour, never implement from a specification alone.

1. Drive the official AutoFirma headlessly (`tools/golden/AutofirmaGolden.java`,
   run with `AUTOFIRMA_JAR=... tools/golden-diff.sh`) to produce its real output
   for a fixed synthetic input.
2. Reduce both sides to a comparable dump with a normalizer that is NOT
   openfirma's own parser for that format, or a bug would appear on both sides
   of the diff and cancel out. CAdES uses our generic DER dumper (safe: it
   understands no signature format); PAdES uses qpdf plus
   `tools/golden/pdf-normalize.py`.
3. Record what differs and why in docs before writing code. Then implement
   until the diff is empty.
4. Add an independent verifier to `cargo test`: openssl, poppler `pdfsig`,
   qpdf, or AutoFirma itself verifying OUR output. Tests skip with a message
   when a tool or the test PKI is absent, and panic instead of skipping when
   material is present but unusable. CI sets OPENFIRMA_REQUIRE_TESTS=1.

## Hard rules

- Pure Rust. No C crypto. No ring, no aws-lc, no TLS provider resting on them.
  RustCrypto modern generation only: digest 0.11, sha2 0.11, hmac 0.13,
  pbkdf2 0.13, aes 0.9, cbc 0.2, des 0.9, rsa pinned `=0.10.0-rc.19`
  (RUSTSEC-2023-0071), p256 0.14, der 0.8, x509-cert 0.3. New dependencies need
  a reason in the commit message and an ADR if they bend a rule.
- Gates before every commit: `cargo fmt --all`,
  `cargo clippy --all-targets -- -D warnings`,
  `OPENFIRMA_REQUIRE_TESTS=1 cargo test`, and the golden diff where one exists.
  All clean, no exceptions, no `#[allow]` to silence clippy.
- Certificate material policy: no certificate, key, keystore or signature made
  with a real certificate ever enters the repository. `tools/check-no-real-certs.sh`
  runs as the pre-commit hook (core.hooksPath tools/hooks) and in CI over the
  index, all tracked files and all history. Test material is generated by
  `tools/gen-testcert.sh` into the gitignored `testdata/certs/`. The synthetic
  PKI covers: natural person with DNI (IDCES-), natural person with NIE
  (IDNIE-), legal person / sello de entidad (CIF in serialNumber plus
  organizationIdentifier VATES- per ETSI EN 319 412-1), representative of a
  legal person, and a TSA. Never assume a signer is a natural person.
- Every commit message ends with exactly this trailer and mentions no AI
  product or session:
  `Co-authored-by: Qwen 3.8 <qwen3.8@millaguie.net>`
- Git: work on branch main, one agent at a time. Commit as one well-described
  commit per coherent change and `git push origin main`. Never rewrite
  history, never force push, never touch .github/workflows unless the task is
  CI itself.
- Errors must name the cause and, where a way out exists, say what to run.
  See the PKCS#12 RC2 refusal and the object-stream refusal for the standard.
- Comments explain WHY, especially where a reader would otherwise "fix"
  something that is deliberate. Document deliberate deviations from AutoFirma
  in docs (see docs/pades.md and docs/adr/0003 for the standard).
- No personal data of any kind in code, comments, docs, commits or test data.

## Definition of done for a feature

- golden diff empty against AutoFirma where a golden is possible,
- an independent verifier in `cargo test`,
- fmt/clippy/test clean with OPENFIRMA_REQUIRE_TESTS=1,
- CI green on all 8 jobs after push,
- README status table and docs/validation.md updated to reality,
- a new ADR when the decision is expensive to reverse.

## Report format

Finish with at most 15 lines: what was implemented, public API added, test
names and counts, commit hash pushed, and each deliberate omission with one
line of reason.
